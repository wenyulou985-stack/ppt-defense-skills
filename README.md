# 给接收 Agent 的使用入口

这是一份用户授权转交的答辩与PPT方法包。适用于中文理工科答辩及相关汇报，不依赖原对话、原机器、原视频或指定制作软件。整理日期：2026-10-12。

## 可直接复制发送的消息

> 请读取附件中的三套 Skill 及相应参考资料，并在后续相关任务中按场景使用。准备真实答辩时，先从我提供的材料提取已知信息，再每轮追问1–3个缺失问题；制作现场PPT时使用逐步动画、章节与小节导航、层次清楚的末页技术总览；独立提交的PPT必须能自行读懂。如果我现在只让你学习，请简短确认接收，不立即开始制作PPT或发问卷。保留我后续提出的具体约束，说明你实际能保存或调用这些规则的范围，不要声称已经永久学习。

## 三套 Skill 怎样配合

| 用户需求 | 使用顺序 |
|---|---|
| 准备毕业答辩、课程汇报、中期/立项答辩、比赛路演 | `defense-prep-coach` 梳理逻辑和问答；需要幻灯片时再用 `ppt-oral-defense` |
| 已有内容，需要制作或修改现场讲解PPT | `ppt-oral-defense`；只追问影响当前任务的材料缺口 |
| PPT交给老师或评委自行阅读 | `ppt-submission-deck`；不能依赖口头说明或动画 |
| 现场讲解和独立提交都需要 | 共用事实与原始图表，分别制作两版 |
| 仅学习此包、仅改字号或指定一页 | 完成指定范围，不强制启动整套答辩问卷 |

`skills/` 下是三个完整的标准 Skill 文件夹，包含入口、参考资料及界面元数据。支持 Skill 文件的 Agent 可按其自身约定导入这三个文件夹，保持它们同级；不支持安装的 Agent 可直接读取本包或合订 Markdown。无需联网或执行安装脚本。

## 本用户的既定要求

- 现场正文按讲述逐步揭示，后续信息和待推导结论不能提前露出。动画要体现推理，不只是末尾几行加出现效果。
- 每页侧栏显示完整章节及小标题，同时定位当前章节和小节；页码另列。
- 末页以统一的“环节—方法／依据”关系组织技术全貌，清楚、整齐、可回指正文，留屏问答。不要堆满表格、流程框和旁注。
- 学习图片与绘图方法：图像须解释结构、机制、对比或结果，不能只作装饰。
- 答辩准备主动追问视频问题库，但先利用已有材料，每轮只问少量问题。

以上是随用户转交的默认偏好，不是所有学校的统一规定。用户当前明确要求、课程/比赛约束优先，冲突时具体说明再调整。

## 来源与使用边界

方法来自用户提供的三段教学视频、迭代修改中的明确反馈及核查记录。视频摘要和问题来源已包含，原始视频、聊天记录、个人通知、原PPT及本机路径不随包分发。引用的是已提炼方法，不表示接收Agent看过原视频。

旧视频约50字、新视频约100字都是现场阅读负担提醒，不作为统一硬门槛。教师的宣传、获奖效果和聊天反馈不当成科学验证或结果保证。

首次读取仅建立当前任务规则；跨会话保存取决于接收Agent能力和用户授权。若不能渲染、制作原生动画或检查实际播放，准确说明限制并交付可用方案，不能把静态截图当作动画验收。
